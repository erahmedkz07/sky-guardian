● Вот честный анализ, что реально стоит доработать:

  ---
  Критические (влияют на демо/диплом)

  1. Исторические временные метки в seed
  Все 48 детекций созданы сегодня → в Analytics chart показывается 1 точка
  вместо 30-дневного тренда. Нужно spread timestamps в seed.ts на -30 дней.

  2. JWT expiry не обрабатывается
  Если токен протух (24ч), API возвращает 401, но фронт не редиректит на /login
  — страницы просто молча падают. Нужен interceptor в api.ts.

  3. Кнопка Reboot в Sensors всегда disabled
  Все сенсоры из БД status = "online", а логика handleReboot запрещает if 
  (s.status === "online") return — то есть кнопку никогда нельзя нажать. Баг в
  логике условия.

  ---
  Важные (качество данных и UX)

  4. Sensor PATCH не пишет в audit_logs
  patchSensor вызывает API, но сервер не логирует действие. Пользователь
  "Reboot/Disable sensor" не отражается в Audit Trail.

  5. feed:event WebSocket только от дронов
  Live Feed показывает события только от drone stream. Новые инциденты и алерты
  не приходят в реальном времени другим операторам.

  6. Калибровка пишет в localStorage, не в DB
  Save Profile в /calibration записывает в localStorage и логирует только
  auditApi.log(). Настройки теряются при другом браузере/операторе.

  ---
  Улучшения качества кода

  7. Ошибки API молча проглатываются
  Почти везде catch { /* ignore */ } — пользователь не знает что пошло не так.
  Нужны toast/inline error сообщения.

  8. PATCH /sensors и PATCH /drones не валидируют IP
  ipAddress в audit_logs берётся из req.ip, но за proxy может быть ::1. Нужен
  X-Forwarded-For fallback.

  9. Форма invite team не проверяет сложность пароля
  Можно создать оператора с паролем "a" — никакой валидации минимальной длины на
   фронте.
